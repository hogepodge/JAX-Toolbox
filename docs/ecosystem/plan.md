# Plan — "JAX on NVIDIA GPU Stack" ecosystem overview page

> Working design doc for the ecosystem-overview feature. Lives in `docs/ecosystem/`
> alongside the feature's config and content. Fern ignores files not referenced
> in the nav, so this file is **not** published to the site.
>
> Status: **planning**. Nothing implemented yet.

## 1. Goal

A single, polished docs page — modeled on Google's
[JAX AI stack](https://docs.cloud.google.com/tpu/docs/jax-ai-stack) page — that
presents the **JAX on NVIDIA-GPU software stack** as a **navigable diagram**.
Selecting a project in the diagram reveals that project's overview beside (desktop)
or below (mobile) the diagram. It must:

- be **NVIDIA-focused** (mirrors the `JAX on NVIDIA-GPU Stack` diagram),
- draw project overview text from **markdown** authored by humans,
- be **configurable** (structure + projects defined in data, not hand-coded),
- **fail gracefully** (missing/invalid content never breaks the page),
- **work in Fern** with no org-gated features.

## 2. Locked decisions (from planning Q&A)

| Area | Decision |
| --- | --- |
| Diagram tech | **CSS-only progressive enhancement** — no JS, no custom React (React is an org-gated Fern feature; we avoid the dependency). Selection via CSS `:target`. |
| Framing | **NVIDIA-focused** overview. The competitive analysis is used only as *source material* for per-project text — no TPU content rendered on the page. |
| Source of truth | **`stack.yml` config + per-project markdown snippets.** |
| Placement | **Single page under the existing "Getting Started" nav section.** |

### Consequence: a build-time generator

CSS-only output can't template `stack.yml` + snippets at render time, so a small
**Node generator** (run via npm script) compiles the config + snippets into static,
MDX-safe diagram markup that Fern serves. This reconciles "configurable / from
markdown" with "CSS-only". Authors edit YAML + markdown, run one command, commit.

## 4. Page structure (information architecture)

File: `docs/ecosystem/jax-on-nvidia-gpu-stack.mdx`, referenced from the
**Getting Started** section in `fern/docs.yml`.

Hand-authored narrative + one generated block:

1. **Title + intro** — what the stack is, who it's for (1–2 short paragraphs).
2. **Interactive stack diagram** — the generated block (see §5–§8). The hero of the page.
3. **How the layers fit together** — short prose tour of the layers
   (Hardware → native-XLA libs → JAX/XLA/Pathways → JAX ecosystem → Frameworks),
   adapted from the competitive analysis (NVIDIA side only).
4. **Tooling & profiling** — short callout linking to existing pages
   (Profiling, nsys-jax, triage tool).
5. **Where to next** — links to framework guides, containers, getting started.

The generated diagram lives between marker comments so regeneration never clobbers
prose:

```mdx
{/* ECOSYSTEM:START — generated by scripts/build-ecosystem.mjs; do not edit by hand */}
... generated diagram + panels ...
{/* ECOSYSTEM:END */}
```

## 5. Interactive diagram — design

### Mechanism (CSS-only `:target`)

- Each project box is an anchor: `<a href="#proj-te" class="eco-node ...">TE</a>`.
- Each project has an overview **panel**: `<div id="proj-te" class="eco-panel">…</div>`.
- CSS hides non-selected panels and reveals the `:target` one:
  ```css
  .eco-panel { display: none; }
  .eco-panel:target { display: block; }
  ```
- A default panel (intro / "select a project") shows when nothing is targeted,
  using `.eco-panel--default` shown unless any sibling is `:target` (or simply
  shown by default and visually replaced).
- Selected node styling via `:target` is not directly available on the anchor, so
  the generator also emits the selected state through the panel + a sibling
  highlight pattern (e.g. `.eco-panel:target ~ … ` is limited; acceptable v1:
  highlight via `:focus`/`:active` + `aria-current` left to a phase-2 polish).

### Layout

- CSS grid: rows = layers, columns = {Tooling, Training/Post-Training, Inference}.
- Core/foundation layers (JAX·XLA·Pathways, native-XLA, Hardware) span full width.
- Diagram + panel: side-by-side on desktop (`grid-template-columns: diagram panel`),
  stacked on mobile (panel below). Driven by a `@media` breakpoint in `main.css`.

### Graceful degradation (explicit requirement)

- **No CSS:** every panel renders (default `display` un-hidden), so the page reads
  as a plain list of projects each followed by its overview. Nothing is lost.
- **No JS:** irrelevant — there is no JS.
- **Missing snippet / unknown project:** generator emits a placeholder panel
  ("Overview coming soon") and logs a warning; the box still renders and links.
- **Hash scroll jump:** `:target` moves the URL hash; mitigate with
  `scroll-margin-top` on panels so the header doesn't overlap. Documented limitation.

### Accessibility

- Real anchors (keyboard + screen-reader navigable), visible focus ring,
  `aria-label` on the diagram region, sufficient color contrast for category fills,
  and category conveyed by **text/legend** as well as color (not color alone).

## 6. Data model — `docs/ecosystem/stack.yml`

```yaml
# Columns rendered left→right.
columns:
  - id: tooling
    label: Tooling
  - id: training
    label: Training / Post-Training
  - id: inference
    label: Inference

# Layers rendered bottom→top (order = vertical position).
layers:
  - id: hardware            # full-width
    label: Hardware
    span: full
  - id: native-xla          # full-width
    label: native XLA
    span: full
  - id: core                # full-width
    label: JAX · XLA · Pathways
    span: full
  - id: jax-ecosystem
    label: JAX ecosystem
  - id: frameworks
    label: Frameworks

# Category = box FILL (origin/ownership) → legend label + CSS class.
categories:
  nvidia:  { label: "NVIDIA-developed / optimized", class: eco-cat-nvidia }
  jax:     { label: "JAX-native / OSS ecosystem",    class: eco-cat-jax }
  other:   { label: "Other / runtime",               class: eco-cat-other }

# Green OUTLINE on a (usually pink) box = NVIDIA contributes to that OSS project.
# Modeled as an independent boolean `nvidia_contributes` per project (see below),
# rendered via the eco-contributes class, with its own legend entry.
contribution: { label: "NVIDIA contributes (green outline)", class: eco-contributes }

# Projects. `overview` points to a snippet under projects/; optional `href`
# links the title out (docs page or upstream).
projects:
  - id: te
    name: TransformerEngine
    column: training
    layer: jax-ecosystem
    category: nvidia
    overview: projects/transformer-engine.md
    href: https://github.com/NVIDIA/TransformerEngine
  - id: maxtext
    name: MaxText
    column: training
    layer: frameworks
    category: jax              # pink fill (JAX-native)
    nvidia_contributes: true   # green outline (NVIDIA contributes)
    overview: projects/maxtext.md
    href: ../frameworks/maxtext/README.md
  # … nsight, nsys-jax, xprof, cupti (tooling);
  #    MaxDiffusion, AxLearn, Grain, Optax, Orbax, Tunix, Qwix, Flax,
  #    Pallas-MosaicGPU, JaxPP, Warp, cuEquivariance, cuTile, CUTLASS, Tokamax
  #    (training / jax-ecosystem);
  #    AlphaFold3, FlashInfer, MLIR-TRT (inference);
  #    JAX, XLA, Pathways (core); cuDNN, cuBLAS/cuBLASLt, NCCL, NVSHMEM (native-xla);
  #    Hardware: Datacenter, Workstation, RTX, Jetson.
```

Schema is validated by the generator (see §8). Unknown `column`/`layer`/`category`
→ warning + the project is dropped from the grid but listed in an "unplaced" panel
(never a hard failure).

## 7. Per-project snippets — `docs/ecosystem/projects/*.md`

- One short markdown file per project (≈40–90 words): what it is, where it sits in
  the stack, why it matters on NVIDIA GPUs. Optional first-line `# Title` ignored
  (title comes from `stack.yml`).
- Initial text drafted from the **competitive analysis** (NVIDIA-side cells) +
  Google page descriptions, rewritten NVIDIA-focused and neutral.
- Authors can edit these without touching code or YAML.

## 8. Generator — `scripts/build-ecosystem.mjs`

Pure Node (no deps beyond a YAML parser already pinnable; or hand-parse a constrained
subset). Responsibilities:

1. Read `stack.yml`; validate columns/layers/categories/projects; collect warnings.
2. For each project, read its `overview` snippet → convert markdown → MDX-safe markup
   (or pass through as MDX). Missing file → placeholder + warning.
3. Emit the diagram (grid of layers × columns of project anchors) + the panel stack,
   into the page between the `ECOSYSTEM:START/END` markers (rest of page untouched).
4. Emit a `<legend>` from `categories`.
5. Print a summary: N projects placed, M warnings (missing snippets, unplaced).
   **Non-zero warnings do not fail the build** (graceful) but are surfaced.
6. Idempotent: same inputs → same output (stable ordering, no timestamps).

npm wiring (in root `package.json`):

```json
"scripts": {
  "docs:ecosystem": "node scripts/build-ecosystem.mjs",
  "docs:dev":  "npm run docs:ecosystem && fern docs dev",
  "docs:check":"npm run docs:ecosystem && fern check"
}
```

(So the diagram is always regenerated before preview/validation.)

### MDX-safety spike (first implementation step)

Fern parses `.md`/`.mdx` strictly as MDX (we already hit a `<>` JSX-parse failure).
Before building the full generator, **spike** a minimal generated diagram (2–3 boxes,
1 panel) and confirm it renders via `fern check` + `fern docs dev`. Resolve the
`class` vs `className` / attribute-quoting question for raw markup in MDX here. If
inline markup proves fragile, fall back to emitting the block as a `.mdx` partial
included by the page. This de-risks the whole approach early.

## 9. Styling — additions to `fern/main.css`

New `eco-*` classes (scoped, won't touch the rest of the site):

- `.eco-diagram` (grid), `.eco-layer`, `.eco-col`, `.eco-node` (box),
  `.eco-node` category modifiers (`.eco-cat-nvidia/.eco-cat-jax/.eco-cat-other`),
  `.eco-contributes` (green **outline** overlay on any fill — composes with the
  category fill class), `.eco-panel` (+ `:target` reveal, `.eco-panel--default`),
  `.eco-legend`.
**Palette (NVIDIA-aligned, no pink).** Fills use NVIDIA green for NVIDIA, a
"JAX Blue" for the JAX/OSS ecosystem, and neutral gray for other. New CSS vars
in `main.css`:

| Token | Light | Dark | Used for |
| --- | --- | --- | --- |
| `--nv-green` (existing) | `#76B900` | `#76B900` | `nvidia` fill + the contribute outline |
| `--eco-nvidia-fill` | `#EAF4D7` | `rgba(118,185,0,0.18)` | `nvidia` box background |
| `--jax-blue` | `#2F6FE0` | `#5B9BFF` | `jax` fill border/title |
| `--eco-jax-fill` | `#E7EFFC` | `rgba(47,111,224,0.18)` | `jax` box background |
| `--eco-other` | `#6B7280` | `#9AA3AF` | `other` (gray) border/title |
| `--eco-other-fill` | `#F1F2F4` | `rgba(148,163,178,0.16)` | `other` box background |

- `.eco-cat-nvidia/.eco-cat-jax/.eco-cat-other` set fill + border from the tokens above.
- `.eco-contributes` overlays a **`--nv-green` border** (e.g. `box-shadow: inset 0 0 0 2px`)
  on top of any fill, so "NVIDIA contributes" reads regardless of fill category.
- JAX Blue is chosen to sit cleanly beside NVIDIA green + the neutral grays
  (cool, mid-saturation; not a clashing primary). Tune the exact hex during styling.
- Responsive: side panel on desktop, stacked below on mobile.

## 12. Validation plan

1. **MDX spike** renders (see §8) — gating step.
2. `npm run docs:ecosystem` produces stable output; warnings summary correct.
3. `npm run docs:check` → 0 errors.
4. `fern docs dev` → diagram renders; clicking a box reveals the right panel;
   default panel shows initially.
5. **Responsive**: desktop side-panel, mobile stacked (devtools check).
6. **Graceful**: temporarily remove a snippet → placeholder + warning, page still builds.
7. **No-CSS fallback**: disable `main.css` → all panels visible, page readable.
8. Spot-check a few project `href`s resolve (relative `.md` rewriting like other pages).

## 13. Risks & mitigations

| Risk | Mitigation |
| --- | --- |
| Raw markup fragile in Fern's strict MDX | MDX spike first; fall back to `.mdx` partial include. |
| `:target` causes header-overlapping scroll jump | `scroll-margin-top` on panels; documented v1 limitation. |
| Selected-node highlight limited without JS | Ship v1 with panel-driven reveal; node highlight is phase-2 polish. |
| Generated block clobbering prose | Marker-delimited injection; generator only rewrites between markers. |
| YAML parser dependency | Use a tiny pinned parser or a constrained hand-parser; keep generator dependency-light. |
| Diagram fidelity vs. the source image | Iterate `stack.yml` ordering/spans against the image; not load-bearing for correctness. |
